# 运行源码、开发仓库与可核验部署

## 源码历史与运行目录

开发和发行以真实 Git 历史为准，在独立分支或 worktree 合并修改。部署目录可能没有 `.git`；`NO_GIT` 只表示缺少提交身份，不表示内容没有变化，也不能在该目录初始化无关仓库冒充发行历史。

运行树与发行树可能有不同平台修复。按文件比较共同基线、已接受运行修改与当前发行代码，保留 Windows 文件身份、跨卷存储和资源定位等现有修复，不能把运行树整树覆盖发行树。数据、模型、账户、报告、`.env`、缓存和私人审计不随源码拷贝。

## 无 Git 审计

`ai_change_logger.py start` 对白名单源码、配置模板和文档记录原 SHA、脱敏文本 SHA、压缩快照与 manifest；`finish` 记录新增、修改、删除及脱敏 diff。业务和秘密目录、权重与符号链接不采集，未读到的文件明确标记不完整。真实 Git 工作区继续使用 Git 事实。

旧会话缺起点快照时保持 unavailable，不补造历史。`finish --external-diff <reviewed-patch>` 可附加已经核验的差异；来源 SHA 与脱敏副本明确标记为外部证据。脱敏快照用于审阅，不是可直接执行的源码备份。详见 [无 Git 审计](no_git_change_audit.md)。

## 部署顺序

1. 冻结完整待部署源码清单和测试证据，核验与当前运行基线的差异；未知新增文件或依赖漂移须先处理。
2. 让依赖旧身份的扫描及任务保存到安全边界，记录可恢复结果。停止相关服务与子进程，核对 owner 身份、端口和写者已退出。
3. 核验行情、模型、账户、关注及必要引用的保护快照，保存精确源码回滚副本。部署中保持应用离线。
4. 每个目标先检查原 SHA，使用同目录临时文件和原子替换；结束后核验完整清单，保存与已验收源码绑定的回执。
5. 重启后检查健康、真实页面/API、模型加载、保护资产及平台入口。冻结身份不匹配的旧任务不可通过改写身份强行续算。

这是维护流程说明，不会自动停止服务或执行部署。任何门槛不满足都不能伪造完成标记继续。

## 回滚与状态

源码回滚使用冻结 manifest 和原始字节，只恢复本次改动；独立修改不得覆盖。多文件回滚也须离线及保护核验。新增缓存统计、任务日志、分页索引采用附加迁移，源码回滚不反向删除这些表，也不隐式回退业务数据。

账户、模型或原始行情恢复使用独立流程。新数值代码有新身份，旧来源、模型和不可变报告保留原身份；取消或中断任务不自动启动。某一操作系统的维护验收不能证明其他平台或最终发行 wheel 已通过。
