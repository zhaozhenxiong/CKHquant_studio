# Agent、MLP 与持仓研究

v1.0.1 的结构分析与全市场扫描支持结构与量价、Kronos、均线 MLP 及同输入 L2 组合，另保留历史参考对照。来源 B/S、预测评分和模拟成交 B/S 分别呈现，缺模型不会伪装成概率零或参考仓位零。方法与预算续批见 [均线组合方法](ma_methods_and_task_maintenance_20261015.md)，本版验证范围见 [v1.0.1 功能验收](v1_0_1_acceptance.md)。

## 证据与账户

本地 Agent 是确定性分析模块：结构和量价提供候选与风险边界，冻结 Kronos 提供采样路径摘要，轻量 MLP 学习组合关系。风险模块逐日检查库存，不等待模型一致。Kronos 采样上涨比例未经独立校准，不等同可靠胜率。

每个比较账户单独使用 BrokerSimulator / Ledger。收盘决策下一核验开盘执行，现金、一手约束、T+1、费用、拒单、待退出、未平仓资产进入账本。结构退出、价格保护、组合回撤及持续证据弱化可以产生卖出；卖出不是要求其它 Agent 全部同意。

委托记录计划股数/仓位变化，成交记录实际负股数、前后库存和仓位百分点变化。不能用目标比例变化冒充真实成交。没有成交时展示主因及其它阻挡条件，夏普保持不适用。

## 轻量训练与检验

历史混合输入 `mixed_v1` 的 A 为24项结构量价数值及10项额外特征缺失标记，共34项；B 加6项Kronos摘要及4种状态，共44项。当前均线输入 `ma_trend_v1` 为20项固定特征，仅支持 A 版，没有附加缺失掩码；其配对 L2 与 MLP 使用相同输入与预处理。小型 PyTorch MLP 和同输入 L2 在相同时间切分上比较。标准化只拟合训练段，校准、政策、留出测试相互隔离；标签必须在各段截止前成熟。候选最多6个、Kronos最多2组、策略最多6组，不无限寻找最高夏普。

`mixed_v1` B 先冻结模型独立的候选/基线持仓人口，历史观察每批最多200次或300秒，累计2000次/10批；失败、无效、延后均保留分母。成熟日期或覆盖不足返回 fusion_data_pending，不自动扩预算或造训练结果。A/B 不代表独立前瞻资格。

研究账户允许检验未晋升候选。每日影子续算须显式选择；自动纸上增仓需要独立政策资格，前瞻认证另行验证，软件发行、训练结束都不晋升。缺评分或过期模型会阻止新风险，但不阻止已有库存的硬风险退出。

四账户比较结构量价、结构量价+Kronos、MLP融合和同输入L2。收益、夏普、回撤、换手、费用、仓位、成交笔数与完整周期共同报告。费用压力必须真实重新回放1/1.5/2倍；配对日期块抽样只描述当前窗口的不确定性。不足5股、3窗、各策略30个完整周期保持pending。预训练范围、未复权行情、公司行为与历史交易规则不足均限制结论。

## 增量与每日链路

“预览结构补齐”输出复用/追加/逐股重建/缺行情/延后差异。执行绑定计划身份；范围可为当前板块、选择、关注、持仓或显式全市场，每批默认20股/300秒。取消为终态，新的明确请求可以复用已提交的检查点。

原生状态以JSON schema、SHA、引擎与几何恢复核验；等价时追加新bar，变更时只重建受影响股票。闭合的256行历史分块可以直接复用；已核验等价的均值和量价状态可续接，方差及部分向量仍完整复算，不承诺所有计算都是追加。板块表格、热图、详情绑定同代身份；局部补齐不冒充全市场full。

日更处理已启用账户和持仓/关注小池，不训练、不自动重启取消任务。回放与续算共用因果日程，持仓和候选共享逻辑预测额度，缓存命中同样计数。超时分别保存完整评估截止与风险截止，迟到预测不得回填成交。

## 本地资产与留存

Kronos-base权重、模型config与tokenizer各保留一份，使用冻结来源校验；公开软件包不附带权重。通过 `KHQUANT_KRONOS_ROOT` 指定本机目录，先运行 `khquant light-research status` 核验缺失项。程序不因打开网页而下载或训练模型。

预览7天/8GiB缓存；必要候选、保存账户和引用对象保护。维护先预览引用，再回收无引用衍生产物；原始行情、模型、账户不作为普通缓存删除。健康检查使用 `khquant verify-workspace --target-date YYYY-MM-DD --strict --json`，默认只读且不加载模型。
