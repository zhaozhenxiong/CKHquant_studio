# 有效机会逐日重评：独立研究版本

内部身份为 `czsc_trend_consensus_v2`，页面名称为“趋势共识策略 · 有效机会重评”。本版本按用户选择改变候选消费与真实持仓普通退出规则，因此重新生成行情特征、候选、账户区间、标签和模型。旧 `czsc_trend_consensus` 模型、报告、训练代码及已发布的0.1.3资产保留原契约。

## 候选与评分

原始机会在首次可见后，只有同时满足原机会有效、账户实际空仓和当日风险合格，才进入当日高收益评分。被质量模型拒绝、缺兼容模型或暂时风险不合格，不消费机会，不启动入场冷却。第二天仍合格时重新评分；单纯持续买方支持不会凭空产生原始机会。

原机会到期仍按首次可见日期计时，不因重评延长。原始冻结边界失效后永久失效，之后价格恢复不会复活同一机会。最终质量、方向总分、身份及风险均通过后，实际账户冻结一次次日开盘入场意图，并保留原机会。等待执行时不重复下单。本版本保持原有单次买入执行语义，Broker拒单不新增买入重试；质量拒绝与Broker执行拒绝分别记录。

每次实际空仓尝试记录信号日、原机会ID、真实账户状态哈希、计划哈希和尝试ID。未评分分别说明无有效机会、风险阻断、持仓不适用、缺模型或输入不合格；不能统一记为0分。高收益概率仅给买方质量贡献，买卖基础权重仍为40%均线、20%结构、30%量价，质量占10%。

## 真实持仓退出

真实持仓的普通退出读取当日持续卖方共识是否通过，不等待新的卖点事件，不受新入场候选或入场冷却控制，也不调用高收益入场质量门槛。硬止损、持仓期限、入场冻结边界及信号时固定的MA持仓退出头仍优先适用。持仓中的退出头不随新检查点升级，L2退出与优势头继续只作影子观察。

卖出拒单或部分成交保留最初卖出意图，后续执行保留真实执行日期与价格。所有成交继续由实际Broker模拟器处理T+1、整手、费用、滑点、成交量及交易价格限制；图表方向、B/S意图与成交分别展示和统计。

## 无循环的训练依赖

训练顺序是新行情冻结与原生特征 → 独立三分类趋势 → 来源政策 → E0实际账户 → 独立MA持仓退出 → 信号时固定先验退出头的E1账户 → 各时间折实际空仓尝试人口 → L2模型。

每个L2时间折开始前，先冻结已经完成的先前线性入场模型目录。参考账户只使用判断日前可用的这些模型；缺先验质量头时阻止参考账户入场，同时保留风险合格的评分前尝试。每个尝试从当时真实空仓状态建立独立标签克隆，强制一次Broker入场，再按已冻结E1续持政策生成完整区间。当前待训练L2头不参与选择自己的训练人口；训练完成后只加入后续时间折目录。标签克隆与参考账户真实交易分别保存。

同一原机会在多日重评不变成多个独立经济样本。入场、收益和亏损头按原机会第一次评分前日期清洗跨段依赖，并在各自选定段内按共享原机会的连通分量加权。持仓退出、退出优势与MA退出头按真实持仓episode切分和加权。两类契约分别保存，不能混用。

训练、校准、政策选择及开发观察按时间分开，标签结束日必须早于相应截止日。报告分别给出截至冻结行情源已清仓的数量与截至该折截止日已成熟的数量；这些数量不冒充通过输入、切分及类别检查的实际训练样本数。未完成清仓、拒单和不合格输入不能当作失败收益标签。

三分类趋势样本或类别不足时保存明确不可用原因，继续预登记的60、180、360股容量级别。某级别完全缺合格趋势头时只生成容量不足探针，不能声称完整依赖训练完成。最新研究自动选择需同时具备最近趋势头、同检查点MA退出头及production入场头。扩池只由缺合格头触发，按预先固定的历史覆盖和股票身份顺序选股；不按收益或事后交易数量选股。

本版本预登记线性L2作为实际评分与后续折参考账户使用的模型，树和MLP仅为受控对照。运行报告的`architecture_selection`与实际模型目录记录执行情况；配置中继承的`search_budget`选择及阈值组合数描述没有在本版本执行，不能据此声称已经选择架构赢家或完成额外阈值搜索。冻结的配置与模型保留原样。

## 行情与身份

新源仅从只读原始行情冻结必要OHLCV、交易价格资格及来源列，不复制旧标签、预测或模型。记录每股原始价基、未核验交易价格条数、遗留价基条数、成交量与金额单位，以及原始文件、核验日历、原生生成器和训练代码哈希。价基不合格的数据保留为不合格输入，不能改标签声称未复权合格。

各阶段写入独立运行目录。训练时检查源和代码身份；加载时校验冻结配置、模型目录、数据集清单及每个模型契约。两代模型在接口、运行报告与页面中明确分族，显式指定的模型不会被自动模式换成其他族。历史重建的检查点可用日期与模型实际完成时间分别保存，不伪写历史部署。

## 新源重建命令

在源代码环境执行，截止日必须是已核验行情截止日：

```sh
PYTHONPATH=app .venv/bin/python -m my_strategy.scripts.train_trend_reassessment --end YYYY-MM-DD --cohort-size 360 --cpu-workers 6 --device cpu
```

`--freeze-raw-only`只冻结新行情；`--raw-source-run-id YOUR_NEW_RAW_RUN --prepare-source-only`只生成新原生输入。随后用 `--source-native-run-id YOUR_NEW_V2_NATIVE_RUN`训练同一不可覆盖的源。`--symbols`可用于功能验证的小池，会明确保留样本不足；正式容量流程不使用它绕过预登记扩池。参数JSON通过 `--config`指定，每个修改后的契约必须生成新运行。

完成训练或有研究自动选择资格，不代表生产或收益认证通过。实际Broker开发评估及源码、配置、模型冻结后的独立前向窗口仍按治理规则验证。`publication_allowed`保持false，旧失败记录和模型不覆盖。

30个交易日市场状态继续使用同一扫描内的实际账户回放与固定股票池，统计口径见[市场状态说明](market_history.md)。没有实际成交时，方向信号不能冒充全市场购买成交。

## 冻结状态的只读重定位验证

`verify_trend_reassessment_relocation` 是独立迁移工具，不在14个训练生成文件闭包中。它不改冻结manifest、模型、标签或配置。原 `finalize_existing_run` 仍按原绝对资产路径审计，不能把该接口在新目录的失败隐瞒成迁移通过；通用 `package --verify` 也未认证此研究族的完整迁移。

先在原运行仍可用时取得其完整completion审计JSON，再生成外置原始收据。若原隔离目录中的日历是符号链接，`--calendar-source` 必须显式指定已核验的原应用日历真实目录，不能直接复制链接。

```sh
PYTHONPATH=app .venv/bin/python -m my_strategy.scripts.verify_trend_reassessment_relocation origin \
  --original-runs-root /original/artifacts/runs --model-run-id YOUR_COMPLETED_RUN \
  --completion-audit /evidence/completion.json --calendar-source /canonical/artifacts/runs/YOUR_CALENDAR_RUN \
  --output /evidence/origin-receipt.json
```

原始收据绑定completion中的报告SHA、冻结身份、完整模型与原始/原生源及日历目录清单。已在冻结清单中的大型文件沿用其原SHA，不声称此时重新读取全部源文件；其他文件在生成收据时按字节取SHA。原始收据是可信本机审计输入，不是公开签名。

将收据列明的完整目录按字节复制到目标后，验证命令只读取目标资产，并拒绝打开旧artifacts根目录。它要求每个原始成员均存在、无额外成员、SHA及大小一致，逐一核对E0、E1、每折六个逐股资产与三个汇总文件，以及整个原始/原生输入股票池和核验日历。日历的父版本和provider原始证据也须完整复制，按冻结SHA验证来源链；每个模型头在新目录冷加载。

```sh
PYTHONPATH=app .venv/bin/python -m my_strategy.scripts.verify_trend_reassessment_relocation verify \
  --original-runs-root /original/artifacts/runs --target-runs-root /target/artifacts/runs \
  --model-run-id YOUR_COMPLETED_RUN --origin-receipt /evidence/origin-receipt.json \
  --output /evidence/relocation-certificate.json
```

收据和证书必须放在冻结运行目录之外，已存在的证据拒绝覆盖。仅核验运行目录时可显式选择 `--scope runtime-only --completion-audit /evidence/completion.json`；此证书的 `complete_state_verified` 永远为false，不能冒充源与标签已完整迁移。原始、个人库和结果索引合并不属于此验证工具；新模型选择及资格也不会因搬迁改变。
