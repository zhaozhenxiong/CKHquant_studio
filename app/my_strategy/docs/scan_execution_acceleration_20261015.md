# CPU 来源准备与单实例预测

`services/method_scan_acceleration.py` 为组合扫描提供独立执行适配器。它复用 `analysis_methods.scan_methods` 字节码，在该次调用自己的全局名字空间替换准备执行器，不修改原模块的全局变量。CPU 准备使用 spawn 进程和原 `prepare_stock` / `LightResearch.source`；工作进程独立打开缓存连接，使用同一冻结原始库、日历和源身份。Kronos 与评分由协调进程按冻结顺序计算，模型保持单实例。

最终调度实现见 [计算与来源优化](compute_optimization_implementation_20261016.md)：来源任务完成后有界补位，应用 worker 上限 4，缓冲受限，逻辑预测预算与输出人口顺序不变。三种方法共享核验通过的结构与预测缓存，缓存命中也按逻辑预算计数。

`compute_info.execution_adapter` 记录适配器、评估器 SHA、有效工作进程和准备累计时间。该累计与协调进程预测可能重叠，不能直接当墙钟时间或与其他阶段相加。执行身份与数值生成身份分开保存，不能改写旧 frozen_identity 或预测键。

工作进程初始化核验实际源代码和冻结依赖；截止时间共享，取消通过事件传播。退出等待所有工作进程结束，不遗留写者。预算是协作边界，最终核验、保存和排空可能超时。进程、IPC、存储故障结束任务，不伪装单股永久缺数据；业务缺失仍保留在完整人口。

切换执行实现需先停止提交新批次、保存当前批次并排空服务，再核验旧行与冻结身份。身份不兼容时须新运行，不能强行续接。普通单股分析保留原入口。

性能比较须核对全部结构、预测路径、评分、质量与人口顺序，区分运行时元数据。ETA 应按实测完整方法轮次的唯一前沿和总方法行推进估计，说明冷/热缓存、间隔与维护时间；单项缓存或小样本进程倍率不能当全市场完成保证。
