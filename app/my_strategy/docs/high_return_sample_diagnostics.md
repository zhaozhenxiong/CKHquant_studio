# 高收益正样本流失诊断

`research-high-return-diagnostics` 对已完成的 `czsc_trend_consensus_v2` 运行生成独立诊断，沿冻结候选、实际 Broker 标签、费用后收益、模型输入、原机会依赖清洗及质量门槛逐层核算。诊断只读取已有训练输入和产物，在新的 `RunContext` 目录保存证据；不重新训练，不改交易规则、模型资格、标签阈值或已有运行。

## 执行

在项目根目录执行，`--model-run-id` 填入需要检查的有效机会重评模型运行：

```sh
PYTHONPATH=app .venv/bin/python -m my_strategy.cli research-high-return-diagnostics \
  --model-run-id YOUR_COMPLETED_TREND_V2_RUN --cpu-workers 2 --json
```

`--cpu-workers` 允许1至4，默认2。进度写入标准错误；标准输出为完整JSON，含新诊断 `run_id` 和 `report_paths`。读取失败、冻结身份不匹配或无法复算的错误沿CLI既有错误处理返回非零。命令成功仅表示诊断生成完成，不授予交易或模型资格。

`report_paths.json` 指向 `reports/high_return_sample_diagnostics.json`，`report_paths.markdown` 指向同目录的 `high_return_sample_diagnostics.md`。每折另外保存 `diagnostics/{fold}/samples.parquet`、`daily_candidate_path.parquet` 和 `clone_rejections.parquet`。JSON中的 `input_assets` 和 `output_assets` 列出路径及SHA256；报告同时绑定冻结模型来源报告、协议和来源快照哈希。核验时先对照来源哈希，再根据样本ID、股票、信号日、原机会ID和标签结束日定位对应记录。

## 看懂样本逐层减少

每个时间折分别报告训练段和校准段，五折之间不合并人口。后续折的参考账户使用已完成的先验质量头，其持仓和空仓尝试人口与较早折不同；把五折直接相加会重复计算经济机会，也掩盖人口变化。

查看以下顺序：

1. **候选人口**：原始机会、当日实际空仓评分前尝试、同机会逐日尝试及依赖块数。风险不合格、持仓不适用、机会无效与缺模型分别披露，不能都解释成质量拒绝。
2. **标签可用性**：克隆入场拒单、未完成持仓、缺下一核验交易日行情、标签未在该段截止前成熟及输入不合格。不可用记录不作为负类；冻结源截止时已清仓也不等于在校准截止前成熟。
3. **收益目标**：校准信号人口中截至冻结来源已完成的可用标签分别统计费用后盈利、费用后收益至少8%、收益至少2R，以及同时满足两者的正类；是否在校准截止前成熟另由过滤漏斗核验。目标是同一完整区间同时通过两条件，不能用盈利样本数代替高收益正样本数。
4. **样本过滤**：按现有模型实现复现特征资格、原机会跨段依赖清洗和段内计权，给出每一步的输入数、保留数、正类数与互斥首次过滤原因。一个样本只在首次失败步骤计一次，独立条件计数不能直接相加当作总流失。
5. **质量门槛**：对已经进入评分人口的样本统计先验质量头通过与拒绝。现有训练人口先记录真实空仓且风险合格的尝试，然后强制一次Broker标签克隆，因此参考账户的质量拒绝不会直接删除该尝试的训练候选。`folds[].segments.calibration.reference_quality` 中的 `quality_rejection_removes_training_candidate=false` 说明这条既有旁路；`high_labels_retained_despite_reference_rejection` 核验参考账户拒绝后仍保留的高收益标签数量。诊断不建立新放行交易，不改变参考账户，也不替代缺模型时的交易规则。

逐样本审计保留原标签和复算结果，包括实际成交价格、费用、滑点、净收益、风险分母、R倍数、成熟日期和过滤原因。费用复算应与冻结标签一致；不一致必须在诊断中明确列为核验失败，不能靠改阈值消除差异。

## 数据与代码对照

| 层级 | 现有生成函数 | 诊断读取的证据 |
|---|---|---|
| 新行情与原生源 | `czsc_trend_v2_source.freeze_raw_source` / `prepare_native_source` | 冻结来源价基、日历、股票池及来源哈希 |
| 每折人口 | `czsc_trend_v2_pipeline.make_reference_population` / `build_stage` | `dataset/final_population/{fold}/manifest.json`，严格先验L2目录 |
| 候选与质量 | `czsc_trend_v2_account.replay_trend_account` | `reference_account.json` 的逐日方向、真实空仓尝试及质量结果 |
| 真实强制克隆 | `czsc_trend_v2_dataset.build_account_dataset` / `clone_candidate_account` | `candidate_clones.json` 的成交、拒单、实际初始止损与标签 |
| 费用后联合目标 | `czsc_trend_v2_labels.episode_outcome` | 实际现金流、费用、净收益、初始风险、R与清仓成熟日 |
| 输入与切分 | `czsc_trend_v2_interval_model.time_masks` / `_weights` | `entries.parquet`，原机会首次日期、原子依赖及连通分量 |
| 样本资格 | `czsc_trend_v2_interval_model.train_head` | 原有100/30行、两段都有两类；与保存的不可用原因比对 |

诊断工具 `czsc_high_return_sample_diagnostics.py` 位于14个冻结训练生成文件之外。它读取原数据、调用原标签与切分规则做核对，不加入新过滤条件。已经存在的旧 `czsc_high_return*_v4` 族与当前逐日重评族的切分契约不同，本命令只接受完成的 `czsc_trend_consensus_v2`，避免混用人口。

## 当前360股production折的基线

2026-10-13排查的360股运行是 `20261013-013547-149508-20261012-czsc-trend-consensus-v2-train-d7ef4eb50a58`，冻结来源行情至 **2026-10-12**。最新 `production` 折校准信号区间为 **2026-07-01至2026-08-13**；信号区间、标签结束日与模型可用时间分别按冻结契约核验。

| 最新production校准层级 | 数量 | 解释 |
| --- | ---: | --- |
| 校准信号候选 | 422 | 过滤前的校准信号人口 |
| 截至冻结来源可用标签 | 411 | 其余11条须按实际原因逐条核验；另查校准截止前成熟性 |
| 费用后盈利 | 220 | 盈利不等于通过高收益联合目标 |
| 费用后收益至少8% | 3 | 收益条件显著减少候选正类 |
| 收益至少2R | 0 | 风险调整目标在此人口中没有命中 |
| 同时至少8%且至少2R | 0 | 进入输入及依赖过滤前已无联合目标正类 |
| 最终校准总数／正类 | 369／0 | 负类369；后续过滤减少数量，未制造缺失的正类 |
| 最终训练总数／正类 | 12,098／206 | 负类11,892；训练段与校准段分开统计 |

这些数字是本次排查基线，实际新报告以所指定运行的冻结输入复算为准。上述校准人口在后续输入及依赖过滤前已有0个联合目标正类，直接缺口来自当前校准区间没有达到联合收益目标的可用标签；411条可用标签及220条盈利标签表明“有交易结果”和“有高收益正类”是不同问题。数据问题仍需依据11条标签不可用、逐样本费用核验及来源身份检查判断，不能由正类为0直接推断行情缺失。

基线中的可用标签有396条按信号时固定的MA退出头清仓；风险比例中位数约8.13%，按2R要求需约16.26%费用后收益，超过单独8%收益条件。报告给出风险比例、所需净收益、实际收益和R倍数分位数，以及按原成交价和冻结分母仅加回费用的联合达标对照，用于识别风险分母、续持退出和费用在当前结果中的作用。这些是对冻结账本的观察，不构成修改退出规则或风险目标的依据。

质量模型会影响后续折参考账户的持仓与空仓尝试，因此质量旁路的结果只对该折冻结评分人口成立。它能核验这些尝试上的直接门槛影响，不能推断全面撤去质量模型后的账户路径或收益。

现有入场模型资格要求训练样本至少100、校准样本至少30，并且训练段和校准段均具备两类。369条校准样本虽达到数量要求，但正类为0，仍明确不可用。诊断保留这一结论；不得合并时间折、把未成熟或拒单样本当负类、降低8%/2R目标、降低质量门槛或修改类别资格来凑正样本。

## 范围和冻结边界

新增诊断模块与CLI在14个 `GENERATING_FILES` 训练生成文件闭包之外。旧模型、标签、manifest、配置、已发布资产和历史失败结果保留原样。输出是开发诊断证据；是否具备实际部署或收益认证资格，仍由原有完整账户审计及独立前向窗口规则决定。

相关候选、标签克隆与依赖清洗契约见[有效机会逐日重评说明](trend_reassessment.md)。
