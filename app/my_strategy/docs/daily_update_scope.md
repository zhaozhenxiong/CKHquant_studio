# 每日行情更新范围与缺数据状态

每日更新、基础资料写入、搜索、新分析与新扫描统一排除北交所。历史北交所业务行由独立维护工具在依赖扫描完成、对比与原保护验收通过后按精确清单退役；日更不会隐式执行历史删除。必要模型、账户、关注、混合来源快照与不可变审计保留，旧报告的冻结人口及身份不改写。`local/db/all_a/custom`、显式股票及实时补充入口均在限量与进度分母确定之前过滤。识别 `.BJ`、`BJ.代码`、`bj代码`、`.BSE` 及北交裸代码；显式 `.SH/.SZ` 优先，沪市 `900xxx` B股不会因首位 `9` 被误剔除。

新板块数学与原生聚合采用独立 `sh_sz_a_v1` 计算投影，分母、覆盖率与成员详情同范围。默认当前视图不会回退旧混合范围；历史版本可显式查看并保留原统计。详见 [北交所退出与板块计算范围](beijing_retirement.md)。

行情提交并通过质量检查后，默认继续同步成员、行情特征、原生结构和板块摘要，无需另开每日定时任务。所有自动同步均要求非空请求已确认有目标日行情覆盖，下载成功但仅返回更早日期不能触发旧日同步。若本次没有新增成功行但已满足覆盖，仍会尝试补齐尚未完成的结构；空请求、没有目标日覆盖或本次质量错误保持跳过／阻断。重复同步受原始内容、日历、成员和生成代码身份约束，成功结果可复用，未完成结果保留恢复检查点。

更新后同步还会把请求日作为 `required_price_date`：实际已核验来源中的最新合格行情日必须精确一致，检查在取得同步租约、刷新成员和发布之前完成。未被接纳的实时或历史来源即使报告当日覆盖，也不能让派生同步回退到更早日期。独立 CLI 可用 `sync-daily-features --price-date YYYY-MM-DD` 执行同样核验；未指定日期的独立同步及网页“同步结构”仍选择实际最新合格日。

更新结果分别记录 `raw_status` 和整体 `status`。行情成功而派生仍忙碌、运行中、失败或部分完成时，整体保持 `partial`，网页显示结构同步未完成及同步 ID，不把行情提交成功当作完整结构发布。显式维护参数 `--skip-feature-sync` 仍可跳过派生同步。

JSON 的 `summary.update_universe` 记录原请求数量、可更新数量、实际选中数量、排除数量及列表；排除股票不计更新失败。`not_updated` 记录已尝试但没有新行情的股票，`target_date_covered` 仅计算缓存真实最后日期达到目标日的股票。原始库中的其他历史股票不因此取得当日覆盖资格。

来源响应的 `empty_range` 只在成功请求、响应身份和日期解析通过后，确实没有目标区间记录时设置。Sina、Eastmoney 和 Tencent 原始行情分别提供此证据。批量逐股请求保留每股 `success/no_data/failed` 及错误原因，不再因其他股票返回成功而丢弃失败。

已有缓存且来源明确返回无新行情时，更新报告为 `skipped`，保留原来的 `last_date`，按真实缓存日期判断目标日覆盖；这并不认定停牌原因或补造今日价格。请求超时、源响应错误、坏行情、未核验空响应仍为 `failed`。没有历史缓存的空响应仍失败。全部股票跳过且没有目标日覆盖时不启动派生特征同步，也不报告新行情完成。

质量检查仅验证本次成功更新或已确认覆盖的股票，窗口截止请求日，不再向未来延长五天；错误仍阻止完成及派生同步，错误详情随结果保留。未更新股票留在更新报告与覆盖统计，后续结构或训练继续使用原有缺失门禁。网页任务错误从完整 JSON summary 提取具体失败数量与质量股票，而非取日志尾部的股票列表。
