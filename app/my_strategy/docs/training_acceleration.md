# 训练缓存与断点恢复

`train-trend` 的模型训练阶段默认经过独立加速适配器；原始冻结、native 准备和原二十五个生成算法保持原入口。已运行的旧训练继续使用启动时的代码，不能原地换算法或用新检查点接管旧半成品。

## 缓存与调度

- `PROCESSED_DATA_ROOT/stock_training/training_cache.db` 保存复用索引；相邻 `training_cache_objects/` 保存压缩的 JSON 内容对象。两者须一同保留。采用 SQLite WAL 和原子对象提交，不保存 pickle。
- 逐股完成后立即补充任务，等待队列有上限。结果先落临时文件，仍按原股票顺序交给上层，保持浮点汇总和输出顺序。
- 模型加载在同一任务内复用，首次核验模型文件与契约，作用域结束再次核验物理 SHA。因果推理缓存绑定准确输入、配置和代码身份；不能仅凭股票代码、日期或文件存在就命中。
- 趋势概率、事件前缀和政策账户分块持久化复用。公共计算只绑定它实际读取的输入与模型，L2 新增的无关模型不会使其失效；整股检查点仍核验完整来源与模型目录。大块决策中间结果的序列化和深拷贝在实测中得不偿失，保持原函数按需计算。
- 逐股标签、探针、资格及观察检查点绑定冻结来源、模型、配置、代码和 run。只有完整成功输出才登记；复用前重新核验依赖和全部产物的 SHA。未经登记的部分输出移到该 run 的隔离目录后计算。
- 模型头、政策选择及表合并分别记录阶段检查点；恢复政策选择时同时恢复原函数对配置、模型束的修改。
- L2 前的 E1 持仓人口完整冻结值另存 `data_snapshots/holding_population.json` 并建立检查点，恢复保留同一冻结时间和身份，避免仅因重新生成时间戳使后续标签与模型检查点失效。
- 独立费用审核仍通过原 Broker 重新计算，只并行调度股票，不用被审核的资格缓存代替审核。

首次计算仍须完成原算法，不能把检查点热读的加速倍数当成全训练加速倍数。适配器不改变 L2 标签定义、折叠时序、成熟条件、费用、风险和模型选择门槛。当前板块成员仍禁止回填历史训练。

## 恢复入口

新训练的 `reports/training_acceleration.json` 单独冻结适配器代码、初始配置、来源、缓存路径及 attempt。模型源码归档继续保留原二十五个生成文件。先检查来源：

```sh
python -m my_strategy.cli resume-training-fast --resume-training-run-id RUN_ID --verify-only
```

`source_verified` 表示来源预检通过；阶段输出的 SHA 在实际恢复使用时逐项检查，不能把预检称为已验证全部检查点。继续同一 run：

```sh
python -m my_strategy.cli resume-training-fast --resume-training-run-id RUN_ID
```

网页训练中心对带加速 sidecar 的 run 选择新恢复入口，其余仍走原 `resume-trend-training`。两入口共用同 run 排他锁，不能同时接管。恢复要求原缓存数据库存在，且代码、配置、设备、人口、日期和来源一致；指定另一数据库、改参数或来源修订都会拒绝。缺失或损坏的派生检查点不能当完成资产，必须通过原计算补齐，原始/native 来源始终只读复用。

部署时如果网页正持有训练资源，保留主进程直到任务结束。新启动的训练/更新子进程能读取新代码；网页主进程内的恢复路由和任务汇总逻辑须安全重启后加载。
