# 趋势共识策略：训练和实际账本验证操作说明

本说明对应 `czsc_trend_consensus` 新模型族，页面名称为“趋势共识策略”。既有模型、标签和账本保持原身份。配置入口为 `configs/czsc_trend_strategy.json`，唯一配置解析器为 `services/czsc_trend_contracts.py`。

## 训练目标与顺序

1. 对全部合格日线训练独立的上涨、下跌、中性三分类均线趋势头。默认从信号日之后第一个核验交易日开盘，到含入场日在内第十个核验交易日收盘，使用价格对数变化分类。上下界为信号时此前 ATR14 与收盘价比值、1% 中较大者的 `log1p`；缺失未来行情、依赖不完整或公司行动不清的观测没有标签，不填成中性。
2. 训练、概率校准和政策选择分别使用按时间分开的区间。每类最低建议 100/30/30 个成熟观测；预处理仅拟合训练段。日历、来源、65 根均线输入和时点可见性核验同时用于训练与使用。
3. 在独立政策段选择预登记的候选交叉及普通方向参数，然后执行不使用高收益评分的 E0 真实账户。
4. 用 E0 已持仓快照训练均线持仓退出头，比较下一核验开盘强制清仓与冻结 E0 续持的实际净清仓收入。未实际清仓的分支不成熟；部分成交累计到真实库存归零。
5. 每个持仓绑定严格早于原入场信号的退出头，形成 E1。没有合格头的持仓全程保持 E0，不在途中升级检查点。重建 E1 实际空仓、具备现金的入场人口和标签。
6. 高收益入场目标为 E1 完整成交区间的费用后收益至少 8%，且至少 2R。R 来自实际初始成交的风险资金。高收益退出头和退出优势头首版只提供影子判断；它们不改变 E1 实际退出。

`p_down` 是独立三类模型输出，不等于 `1-p_up`，也不代替真实持仓退出概率。图表方向点、账户意图、实际成交分别保存。

## 从仓库根运行

```sh
PYTHONPATH=app .venv/bin/python app/my_strategy/scripts/train_trend_consensus.py \
  --cohort training --cpu-workers 6 --device cpu
```

CLI 打印每个不可变 `TRAIN_RUN_ID`。训练使用完整原始历史预热，仅目标人口从配置的 `feature_start` 开始，不先裁掉均线、风险或结构历史。

如固定 60 股不足以训练最新持仓退出头或生产入场头，按预登记 60→180→360 阶梯扩容。额外股票来自冻结主板资料，依据 `seed=42` 与股票代码哈希排序，并核验 2023 年之前的输入历史。扩容不读取开发收益，校准门槛不降低，固定 60 股开发验证池不扩张。每个阶梯生成独立原生快照、标签、模型和运行目录；失败及缺头结果保留。

```sh
PYTHONPATH=app .venv/bin/python app/my_strategy/scripts/train_trend_consensus.py \
  --resume-run-id <已完成或仅收尾失败的训练运行ID> \
  --cpu-workers 6 --device cpu
```

`--resume-run-id` 先审计既有产物，随后只在最新必需模型不足时继续更高容量阶梯。它不在原目录继续生成新标签或覆盖旧检查点。

## 收尾类型适配

冻结管线原收尾 SHA 校验曾把字符串路径直接送入只接受 `Path` 的工具。官方 CLI 对 SHA 工具参数进行 `Path` 归一化，路径对应的字节和散列值不变，九份生成源码保持冻结。

`czsc_trend_finalization.finalize_existing_run` 仅用于已有完整标签和模型的收尾审核：它检查九份最初源码 SHA、E0/E1 目标与配置、所有账本/标签文件散列、物理模型及目录清单，再生成新的完成记录。源码变化、已有完成或拒绝报告、目标不匹配均拒绝恢复。它不重新拟合、不回填真实训练时间，也不覆盖已完成报告。

## 实际 Broker 验证

先运行三只控制股，再运行固定 60 股开发池：

```sh
PYTHONPATH=app .venv/bin/python app/my_strategy/scripts/validate_trend_consensus.py \
  --model-run-id <新模型运行ID> --cohort controls --cpu-workers 3

PYTHONPATH=app .venv/bin/python app/my_strategy/scripts/validate_trend_consensus.py \
  --model-run-id <同一新模型运行ID> --cohort training --cpu-workers 6
```

每股每窗口为独立 10 万元现金账户，无共享现金。冻结开发窗口为 2025Q2、2025Q4、2026Q2、2026Q3，另保存 2026YTD 展示；数据截止以训练报告为准。正常及双倍滑点分别重放 E0、E1、线性主模型和 tree/MLP 消融，并配对原冻结控制账本。双倍滑点是同一名义训练目标的执行压力诊断，不宣称已按双倍费用重新训练目标。

每个账户保存 Ledger 成交、每日净值、拒单、未平仓持仓、原始意图和模型诊断，核验意图到成交、收盘意图不得同日开盘成交、现金与库存守恒。单个标的准备失败仍保存该标的所有请求账户的初始现金并披露错误。

等额账户净值在核验日历上按各账户的初始现金起算，只向前延续已发生的净值。缺日期不视为零资产，也不借用未来日期报价回填。早期 180 股模型的固定 60 股验收曾出现直接对已有行求和的汇总错误；真实成交、账户现金与个体每日账本未改，旧报告保留。使用以下命令在独立运行目录校验原资产 SHA、现金/库存/费用/区间计数并重新汇总，报告明确记录原验收 ID、3600 账户复用及零账户重新生成：

```sh
PYTHONPATH=app .venv/bin/python app/my_strategy/scripts/reaggregate_trend_validation.py \
  --parent-validation-run-id <原始验收运行ID>
```

报告为 `reports/trend_Broker_validation.json`。主线采用预登记线性模型，tree/MLP 为消融，不从已读开发窗口反选赢家。四个互不重叠开发窗口要求至少 200 个完整区间且每窗至少 50 个；YTD、不同滑点及消融不累加为独立样本。

高收益入场阈值 0.1、最终买方总分门槛 0.5 仍为预登记基线，不能称为已按收益优化选出的参数。候选交叉和普通方向参数仅以报告保存的独立政策期选择结果为准；校准概率、政策选择和已读开发诊断的用途分别披露。

## 20 日趋势目标敏感性

用同一最终训练池、原生资料和核验日历独立重建 H20 标签及十二个时间拆分的三分类头。主模型完成后可直接运行：

```sh
PYTHONPATH=app .venv/bin/python app/my_strategy/scripts/train_trend_sensitivity.py \
  --model-run-id <完成的H10主模型运行ID>
```

最终训练池已固定、十二个 H10 趋势头已真实完成，而主模型仍在后续政策或账户训练阶段时，可显式使用 `--allow-trend-stage-source` 提前运行。此入口核验九份生成源码 SHA、原始资料清单、完整核验日历、物理趋势模型、目录及观察标签契约。它保留父运行 `in_progress`，不生成主模型完成报告，也不使用尚未完成的候选、普通 SELL、E0/E1 或高收益参数选择。线程上限为 2，不改变主训练资源。主模型完成后另保存来源一致性核验，早期阶段来源状态不会被悄悄改成完成。

该运行不复用 H10 标签或检查点，不重训 E0/E1/L2，报告为独立目录中的 `reports/trend_sensitivity.json`。H10 与 H20 的成熟覆盖、各类计数和校准/政策指标按相同时间段并列披露；二者目标不同，不根据已读开发收益反选 H20。头未达到成熟类别门槛时记录不可用及实际计数，不填评分。该敏感性运行始终不能自动选择或用于生产。

## 参数与模型兼容

改变趋势目标、H、阈值边界、输入资格、原生证据、入场候选、风险边界、普通 SELL 或持仓退出政策，需要按依赖顺序重建对应目标和下游模型。E1 入场标签不能复用于改变续持后的 E2。启用 L2 实际退出前必须先冻结新的退出政策，再生成匹配该政策的入场标签和独立模型。

本版真实账本采用 CostModel 连续滑点模拟成交均价。高收益标签的初始 R 则使用已冻结的假设止损卖出参考：对止损边界施加卖出滑点后，按 0.01 元 HALF_UP 取分，再扣费用，与实际初始买入扣款相减。它是参考风险单位，不是已发生的真实止损损失；开盘跳空也可能产生更大实际损失。持仓保护与特征的止损几何距离使用同一实际冻结边界，没有把未来标签 R 放入模型输入。180 股只读敏感性审计发现改成连续参考 R 时 E1 成熟标签不翻转、E0 描述性入场标签有一处翻转；此结果不能推广为以后永不翻转。改变这个假设需要独立新契约和重建，既有 manifest、标签及账本不改。

默认加载仅选择已完整审核、H10 主族、最近必需头合格的运行。显式指定缺头研究运行可查看缺失原因，但缺失概率不填 0。固定检查点不得用于其可用时点之前。

## 结果边界

已读四历史窗口只作开发诊断。未来独立验证从协议、代码、配置和全部实际模型冻结后的首个核验交易日起计，尚未完成时保持 `pending`。有限训练池不等于全市场验收；未复权价格、历史 ST 和时点股票池资料限制随报告披露。样本不足、收益或费用压力检查未通过均不能称为发布资格或收益保证。
