# 同花顺板块知识库和模型特征建设计划

在 `DATA_ROOT/raw/stock_basic/basic_kb.db` 建立独立的同花顺板块知识库，保存股票基本身份、行业与概念目录、成员归属历史和可复用的板块特征。板块特征用于补充个股的市场环境，后续进入综合入场、实际持仓退出和独立参考质量模型。

本轮交付为计划。当前运行中的训练保持已冻结的来源、特征、参数与生成码；新增板块输入使用新的特征契约和独立训练任务。

## 现有数据和可复用代码

2026-10-14 只读核验：原始 SQLite 的 `stock_basic` 有 5572 只股票，快照时间为 2026-10-08 23:38:24。可直接使用代码、名称与来源时间；当前记录没有行业、概念或上市退市时间，固定列中的价格、市值和换手率为空。原始日线截止 2026-10-12。

原始库已有行业元数据、排除及更新记录表，但数据为空。现有 `market_sector_snapshot.json` 是新浪申万一级当前快照，包含 31 个行业并覆盖 5572 股。该快照保留独立来源和分类体系。

`data_manager/sector_provider.py` 已有同花顺目录和成员解析骨架，可复用板块身份、代码规范和解析方法。实施时须补强完整分页和成员稳定性校验：缺分页标记时不能默认完整，按实时排序分页可能发生跨页移动；超过匿名可读取范围的板块必须保留失败原因。已有混合提供器包含其他来源，不作为本计划的同花顺数据来源。

## 数据来源和采集范围

首版同时覆盖同花顺行业与概念。目录从[同花顺行业](https://q.10jqka.com.cn/thshy/)和[同花顺概念](https://q.10jqka.com.cn/gn/)读取，成员与说明从对应板块详情取得。保留来源原始代码，使用现有 `THS_I_原码`、`THS_C_原码` 身份；不同分类体系、产品和行业层级分别标识。名称变更追加名称记录，板块合并、拆分保留关联，不凭名称相同合并不同代码。

以板块为单位采集成员，再反向建立股票归属，避免逐股重复读取相同板块。先试采银行、半导体、汽车整车及若干多成员概念，覆盖多页和大型板块。核对来源总数、各页数量、重复成员、完整代码集合及采集前后状态。接口不能证明完整时，该板块保持未完成，不把部分结果升级为完整快照。

同花顺官方数据平台列出[按股票和日期查询的个股概念表](https://quant.10jqka.com.cn/view/dataplatform/detail/73)及[行业分类信息](https://quant.10jqka.com.cn/view/dataplatform/detail/24)。历史训练优先核验这类带日期的同花顺数据。实施第一阶段确认账号或合法导出方式、可读取日期范围、成员变更记录和历史可用时间；公开目录可访问不代表本机已取得历史接口权限。

采集使用限速、有限重试和断点恢复。拒绝访问、限流或内容截断须明确报告，保留上一份完整快照；不会将采集失败写成板块空成员。接口权限不足时可接收来源可核验的同花顺导出文件，仍执行相同的身份、完整性和时间检查。

## 数据库设计

本机目标位置为 `app/my_strategy/data/raw/stock_basic/basic_kb.db`。实现中由 `core.paths` 定义路径，跟随配置的数据根迁移，不写死本机绝对路径。原始行情继续保留在现有原始库，知识库只保存基本资料、板块事实和特征。

| 表 | 用途 |
| --- | --- |
| `stock_basic` | 规范股票代码、名称、交易所、来源及基本资料版本；上市退市日期仅在有可信来源时填写 |
| `board_catalog_versions` | 行业与概念的原始代码、名称、分类体系、层级、生命周期和修订记录 |
| `board_snapshots` | 每批目录及成员快照的来源、时间、成员数量、完整状态、哈希和验证结果 |
| `stock_board_membership` | 股票与板块的多对多关系，引用不可变快照，保存有效时间和已知时间 |
| `source_payloads` | 来源原始响应或导出内容、压缩数据、物理 SHA、来源地址及采集时间 |
| `board_daily_features` | 每个板块每日的数值特征、覆盖情况与生成身份 |
| `stock_board_features` | 每股每日的行业环境、概念摘要、个股相对强弱及可用性 |
| `refresh_runs` | 更新批次、完成与失败板块、断点、错误和更新结果 |

行业归属与概念归属分开保存；一只股票允许同时属于多个概念。股票在来源中存在但基本表尚未收录时，保留待核验身份和原因，不能因当前名单缺失而静默删除历史成员。

快照与修订追加保存，当前查询通过视图选择适用版本。只有两份完整快照才可生成成员差分；差分的观察时间不冒充成员真实加入或退出时间。完整目录快照确认的板块退役与采集失败分开表达。

SQLite 使用 WAL、事务和单协调者写入，读者只读。失败批次不得覆盖完整批次，同一输入重复导入保持幂等。索引围绕股票、板块、日期、快照及可用时间建立；数据库、原始采集内容和运行状态遵循现有私有数据与备份规则。

## 历史时点约束

每份资料分开保存 `effective_at`、`observed_at`、`available_at`，并保留来源发布时间和本次获取时间。有效时间表示资料适用的时期，观察时间表示本系统何时取得，可用时间表示有证据支持的最早决策使用时间。

历史读取同时验证归属在该日生效且当时已可用。来自当前网页的成员关系从实际观察后开始积累，不向过去回填。即使接口有历史日期，也需核实该日期表示历史归属还是后来修订的归属；没有历史发布时间证据时，不伪造当时可用时间。盘后首次取得的资料不能用于当天 15:00 的判断。

当前原始行情截止 2026-10-12。本轮新采集的当前成员快照不能直接加入截止该日的历史训练。若能取得经核验的历史成员及可用性证据，按实际覆盖区间建立历史特征；否则旧日期明确缺失，先提供当前展示并积累后续可训练资料。

未知、有效零值、陈旧快照和输入质量失败分别表达。没有概念、尚未采到概念与板块真实无活跃成员不能混为一个值。滚动指标仅使用截至决策时点的行情；归一化和类别词表只在训练段拟合。

## 首版板块特征

首版先使用成员归属和已有本地日线，形成可审计的行业与概念环境。每个板块每日计算一次，再映射到股票，训练重跑直接读取同身份结果。

| 类别 | 首版指标 |
| --- | --- |
| 价格强弱 | 1、5、10、20 个交易日板块组合收益 |
| 趋势广度 | 上涨成员比例、站上 MA20 比例、突破此前 20 日高点的成员比例 |
| 量能 | 总成交额、全市场成交额占比、相对此前 20 日的成交额强度 |
| 风险 | 20 日收益波动、20 日最大回撤 |

本地板块组合首版采用明确的等权成员收益口径，保留有效成员数、预期成员数、价格基础和权重定义。它与来源提供的官方板块指数分别存储、分别命名。成员不足、行情覆盖不足或价格基础存在问题时，指标不可用；覆盖门槛和最小成员数在试采验收后预先冻结。

个股侧补充相对行业的 1、5、20 日收益和行业内 20 日强弱分位。行业环境映射一份；多概念环境按预先固定的均值、中位数、最大强度及有效数量汇总，不把一股多概念展开成重复训练样本。同行比较排除该股票本身，保存分母和缺失标记。

第二阶段再评估板块内 CZSC 买卖证据密度、威科夫需求供给强度和事件广度。只消费身份、日期、人口覆盖均合格的已有 native 产物，不在板块查询时重算每只股票的 CZSC 或威科夫。

特征缓存绑定成员快照、行情内容、核验日历、价格基础、计算口径、schema 与生成码 SHA。输入、公式或成员变化时重算受影响区间；滚动窗口和累计路径的后续依赖一并失效。模型训练轮数、学习率和 batch 调整不改变板块特征身份。未来新增交易日只计算新日期及其依赖，历史修订保留独立版本。

## 页面和训练接入

页面先接入行业、概念标签及板块强弱展示，标明来源、资料时间、价格日期和历史可用性。历史分析默认读取当时可用的归属；当前归属展示须清楚标注当前口径。市场扫描可以按行业或概念过滤，并读取已缓存的板块强弱。

模型侧建立独立的板块特征 profile 和有序输入契约，作为综合入场、退出、退出优势及参考质量模型的上下文。独立趋势与均线模型保留既有输入契约。行业代码采用有身份的类别处理，不把编码大小当强弱；训练段未出现的类别使用未知标记。

有合格历史来源后，按新 schema 冻结来源、重建受影响样本和标签，启动独立新任务。当前训练不追加列、不原地换参数或改变生成码。原始来源和 native 复用仍按既有身份检查决定；任何触及 native 生成逻辑的修改继续遵守其重建规则。

评估先比较相同时间窗口、相同总体人口中“现有特征”和“加入板块特征”的费用后表现，完整披露因板块缺失造成的有效样本变化。收益改善、回撤、换手、费用压力及资格全部按既有门槛验收。8% 且 2R、完整成熟、严格先验、实际持仓退出人口和自动选择条件保持。

## 实施顺序和验收

1. **来源试采与时间核验**：测试目录、普通板块、多页板块和大型概念；确认历史数据权限、成员日期与可用时间。产出来源契约、完整性报告和历史覆盖报告。
2. **建库与快照导入**：建立 `basic_kb.db` 和读写适配器，从现有基本表导入股票身份，再导入完整同花顺目录与成员快照。产出覆盖、未知、冲突和失败清单。
3. **更新与历史查询**：实现幂等导入、追加修订、完整快照差分、失败保留及按日读取；提供独立 CLI 更新和查询入口。每个交易日收盘后可显式执行一次更新，周期调度另行配置。
4. **数值特征与缓存**：实现上述 12 项板块指标及个股关联特征，用小样本手工核对公式、分母、概念去重和同行排除；保存身份与失效范围。
5. **页面展示**：在现有结构分析、扫描和数据入口显示来源、归属、覆盖及强弱，不在用户访问时发起全量计算。
6. **新任务训练与消融验收**：历史来源条件满足后，冻结新 schema 和协议，生成新任务并比较模型效果。历史条件未满足时，交付已验收知识库、当前展示和未来数据积累，模型接入保持 pending。

验收必须覆盖：沪深北代码与重复归属；分页缺失、同数量换成员和限流；失败快照不删成员；重命名及板块合并拆分；历史有效时间与可用时间；盘后快照边界；历史概念未出现时的缺失；多概念不重复加权；停牌和行情覆盖分母；缓存命中及行情、成员、公式修订失效；并发读写和中断恢复；新输入训练段归一化及完整时间切分；当前训练来源、参数和生成码保持。

首阶段完成条件是“完整、来源可追溯的同花顺知识库”，模型阶段完成条件另含“可验证历史成员和可用时间”。这两个条件分别验收，使板块信息能够先用于可靠展示，再按实际历史覆盖取得训练输入资格。
